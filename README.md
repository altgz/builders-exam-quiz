# 二级建造师刷题

一个纯静态的二级建造师刷题网页，HTML + CSS + 原生 JavaScript 实现，无构建步骤、无后端、无第三方依赖，可直接部署到 GitHub Pages。

- 题型覆盖：单选、多选、判断
- 练习模式：顺序练习、随机练习、错题重做、收藏夹练习、限时模拟考试
- 作答反馈：单选/判断点击即判，多选需手动提交；正确标绿、错误标红并标出正确答案，附解析
- 学习数据：做题记录、错题本、收藏、考试历史全部保存在浏览器 localStorage
- 统计：总正确率、各章节掌握情况、考试历史
- 界面：移动端优先、顶部进度条、底部操作栏、深色模式（跟随系统 + 手动切换）

## 文件结构

```
outputs/
├── index.html          # 入口页面（密码门、页面骨架与各视图结构）
├── style.css           # 全部样式，含深色模式变量
├── app.js              # 全部交互逻辑：密码校验、题库加载、判题、存储、计时、统计
├── questions.json      # 完整题库（602 题）
├── questions-data.js   # 由 questions.json 生成的兜底题库，供 file:// 直接打开时使用
└── README.md           # 本说明
```

网站根目录就是 `outputs/`，部署时把该目录内的文件放到站点根目录即可。

## 访问密码

密码集中配置在 [app.js](app.js) 顶部：

```js
// ===== 访问密码：修改下面这一行即可更换站点密码（区分大小写）=====
const ACCESS_PASSWORD = 'Yuanzhi2026';
```

- 打开页面先显示全屏密码页，输入正确密码后才加载题库；未解锁时不会请求 `questions.json`。
- 解锁状态保存在 `localStorage` 的 `bq:unlock:v1` 中，只存密码散列，不存明文；刷新后免重复输入。
- 顶栏右侧的「锁定」按钮会清除解锁状态并返回密码页。
- 修改密码后，已解锁设备因散列不匹配会自动要求重新输入。
- 这是纯前端校验，密码和校验逻辑都在浏览器中，无法阻止查看源码，只适合轻量访问控制，不能替代服务端鉴权。

## 本地预览

推荐通过本地 HTTP 服务打开：

```bash
# 方式一：Python（Windows 一般已安装，或从 python.org 安装）
cd outputs
python -m http.server 8000

# 方式二：Node.js
npx serve .
```

然后浏览器访问 <http://localhost:8000>。手机与电脑在同一局域网时，可用电脑局域网 IP 访问，例如 `http://192.168.1.10:8000`。

也可以直接双击 `index.html`：浏览器会阻止 `fetch` 读取本地 `questions.json`，页面会自动回退加载 `questions-data.js` 中的内联题库，因此仍能正常刷题。修改题库后请按下方说明同步更新兜底文件。

## 题库格式

`questions.json` 由 `meta` 和 `questions` 两部分组成：

```json
{
  "meta": {
    "title": "二级建造师刷题",
    "subject": "建筑工程管理与实务",
    "version": "2.0.0",
    "updatedAt": "2026-11-18"
  },
  "questions": [
    {
      "id": "single-001",
      "subject": "建筑工程管理与实务",
      "chapter": "单选题",
      "type": "single",
      "stem": "下列属于永久作用是（ ）。",
      "options": ["温度作用", "风荷载", "预应力", "地震"],
      "answer": ["C"],
      "analysis": ""
    }
  ]
}
```

### 字段说明

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | 字符串 | 题目唯一标识，如 `single-001`。**不要重复**，改了 id 会丢失该题的历史记录。 |
| `subject` | 字符串 | 科目名称，首页「科目」下拉框由此生成。 |
| `chapter` | 字符串 | 章节/分类标签，首页「章节」下拉框与统计页按此聚合。建议同一章节使用完全一致的文字。 |
| `type` | 字符串 | `single`（单选）、`multiple`（多选）、`judge`（判断）。 |
| `stem` | 字符串 | 题干，纯文本。 |
| `options` | 字符串数组 | 选项内容，**不要带 `A.` `B.` 前缀**，页面会自动生成字母编号。判断题固定写 `["正确", "错误"]`。 |
| `answer` | 字符串数组 | 正确答案的选项字母，如单选 `["B"]`、多选 `["A","C","D"]`。判断题正确填 `["A"]`，错误填 `["B"]`。只有源文件确实缺答案时才允许空数组。 |
| `analysis` | 字符串 | 答案解析，纯文本；源文件没有解析时留空。 |

### 新增 / 替换题目注意事项

1. 保持 JSON 合法：使用 UTF-8 编码，双引号，最后一项后面不能有逗号。建议用支持 JSON 校验的编辑器检查。
2. `answer` 里的字母必须与 `options` 下标对应：A=第 1 项、B=第 2 项，以此类推，最多支持 5 个选项。
3. 多选题的答案顺序不影响判题，`["A","C"]` 与 `["C","A"]` 等价，但建议按字母顺序书写。
4. 判断题统一使用 `options: ["正确","错误"]`，不要只写一个布尔值，保证三种题型的数据结构一致。
5. `subject` 与 `chapter` 是筛选和统计的依据，新增时尽量复用已有名称，避免出现「混凝土结构工程施工」和「混凝土工程施工」两个相似章节。
6. 替换整批题库时，保留原 `id` 可延续做题记录；如果全部使用新 `id`，历史记录不会自动迁移，可在统计页清除本地数据后重新开始。
7. 题库规模变大后（上千题），`questions.json` 仍是全量加载，首次打开会稍慢；纯静态方案下这是可接受的取舍。
8. **每次修改 `questions.json` 后，必须重新生成 `questions-data.js`**，否则直接双击 `index.html` 时仍会读到旧题库。可在 `outputs` 目录执行：
   ```bash
   node -e "const fs=require('fs');const d=fs.readFileSync('questions.json','utf8');fs.writeFileSync('questions-data.js','window.__QUESTIONS_FALLBACK__ = '+d+';\n')"
   ```

## 部署到 GitHub Pages

1. 在 GitHub 新建一个仓库（公开或私有均可，Pages 对私有仓库的可用性取决于账号套餐）。
2. 把 `outputs/` 目录内的全部文件上传到仓库根目录，确保根目录直接能看到 `index.html`：
   ```bash
   cd outputs
   git init
   git add .
   git commit -m "feat: 二级建造师刷题"
   git branch -M main
   git remote add origin https://github.com/<你的用户名>/<仓库名>.git
   git push -u origin main
   ```
   也可以在网页端直接拖拽上传这些文件。
3. 打开仓库的 **Settings → Pages**。
4. 在 **Build and deployment** 中，Source 选择 **Deploy from a branch**，Branch 选择 `main`，目录选择 `/ (root)`，点击 **Save**。
5. 等待 1～2 分钟，访问 `https://<你的用户名>.github.io/<仓库名>/`。
6. 之后更新题库时，替换 `questions.json` 并同步重新生成 `questions-data.js`，提交后 Pages 会自动重新发布。

> 如果使用自定义域名或仓库名不是 `<用户名>.github.io`，页面路径会带上子路径。本项目的资源均使用相对路径（`style.css`、`app.js`、`questions.json`），无需额外配置。

## 本地存储数据结构

存储键名有两个：`bq:v1`（学习数据）和 `bq:unlock:v1`（解锁状态，值为密码散列）。

`bq:v1` 的值为一个 JSON 对象：

```json
{
  "version": 1,
  "records": {
    "single-001": {
      "attempts": 2,
      "correct": 1,
      "lastAnswer": ["C"],
      "lastCorrect": true,
      "lastAt": 1763510400000
    }
  },
  "wrong": {
    "single-185": { "count": 2, "at": 1763510400000 }
  },
  "fav": {
    "single-003": true
  },
  "exams": [
    {
      "id": "exam-1763510400000",
      "at": 1763510400000,
      "total": 10,
      "correct": 8,
      "score": 80,
      "usedSec": 420,
      "size": 10
    }
  ],
  "settings": {
    "theme": "auto"
  }
}
```

| 字段 | 说明 |
| --- | --- |
| `records[id]` | 单题累计作答：`attempts` 总作答次数、`correct` 答对次数、`lastAnswer` 最近一次所选字母、`lastCorrect` 最近一次是否正确、`lastAt` 时间戳。练习与模拟考试中已作答的题都会计入。 |
| `wrong[id]` | 错题本：`count` 累计答错次数、`at` 最近答错时间。答错加入，之后任意一次答对自动移除。 |
| `fav[id]` | 收藏标记，`true` 表示已收藏。 |
| `exams` | 考试历史，最新的在前，最多保留 20 条。`total` 题量、`correct` 答对题数、`score` 百分制得分、`usedSec` 用时秒数、`size` 本场抽题数。 |
| `settings.theme` | 主题：`auto` 跟随系统 / `light` 浅色 / `dark` 深色。 |

另有 `bq:unlock:v1`：保存密码散列用于免重复输入，不包含明文密码；点击顶栏「锁定」会删除该项。

其他说明：

- 已做题数按「有作答记录的题目数」统计，同一题重复作答不会重复计数。
- 总正确率 = 累计答对次数 ÷ 累计作答次数；章节正确率同样按作答次数计算。
- 模拟考试交卷时，未作答题目按错误计分，但不会写入做题记录；已作答题目正常写入记录与错题本。
- 5 道缺少答案的题不会进入练习或考试，因此不会产生做题记录。
- 数据只存在当前浏览器、当前域名下。清除浏览器数据、更换设备或更换域名后不会保留。
- 可在「学习统计」页底部点击「清除全部本地数据」重置所有学习记录（不影响解锁状态）。

## 浏览器兼容性

面向现代浏览器（Chrome / Edge / Safari / Firefox 近两年版本），使用了 `fetch`、CSS 变量、`color-mix`、`backdrop-filter`、`dvh` 等特性。旧版浏览器可能缺少部分视觉细节，但核心答题功能不受影响。
